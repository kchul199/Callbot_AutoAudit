## 3. 파이프라인 단계별 설계

### 3.1 CP1 — 전처리 (`cp1_preprocessing/parser.py`)

```
입력: data/raw/ (txt | json | csv 콜 로그 파일)
출력: list[CallLog]

CallLog {
  call_id, subscriber_id, started_at, ended_at,
  turns: list[ConversationTurn {turn_id, role, content, timestamp}],
  metadata: dict
}
```

- `CallLogParser` 클래스: 확장자 기반 포맷 자동 감지
- `min_turn_length=5` 미만 턴 필터링 (너무 짧은 인사말 등)
- 결과를 `Tracer`를 통해 `data/results/run_{id}/cp1_call_logs_{ts}.json`에 저장

---

### 3.2 CP2 — 지식 베이스 (`cp2_knowledge_base/`)

#### 청킹 전략: Parent-Child Chunking

```
CallLog 전체 텍스트
         │
         ▼ (슬라이딩 윈도우, 1000 words)
   Parent Chunk ──── 컨텍스트 제공 (검색 후 확장)
         │
         ▼ (슬라이딩 윈도우, 200 words, overlap 50)
   Child Chunk  ──── 벡터 인덱싱 대상 (검색 Precision 최적화)
         │
         └─── parent_chunk_id 참조 → 검색 후 부모 청크로 확장
```

**설계 근거**: Child 단위로 검색해 Precision을 높이고, 실제 컨텍스트 제공 시 Parent로 확장해 Recall도 확보.

#### 인덱싱

```
인덱싱 대상: Child 청크만
임베딩 모델: text-embedding-3-large (3072차원)
유사도: cosine (HNSW space=cosine)
저장소: ChromaDB PersistentClient (data/chroma_db/)
Mock 모드: InMemoryVectorStore (chromadb 미사용)
```

---

### 3.3 CP3 — 검색 (`cp3_retrieval/retriever.py`)

#### HybridRetriever 파이프라인

```
질의(Query)
    │
    ├─① HyDE (Hypothetical Document Embeddings)
    │      가상 이상적 답변 생성 → 실제 문서에 가까운 임베딩
    │
    ├─② Multi-Query
    │      3가지 다각도 변형 질의 생성
    │
    ▼
[질의 pool: 원본 + HyDE + Multi-Query]
    │
    ├─ Dense Search  (임베딩 cosine 유사도, ChromaDB)
    └─ BM25 Search   (희소 키워드 매칭, rank-bm25)
    │
    ▼
③ Weighted RRF (Reciprocal Rank Fusion)
   weight: dense=0.7, bm25=0.3, rrf_k=60
    │
    ▼ (상위 top_k=20)
④ Cross-Encoder Reranking
   모델: cross-encoder/ms-marco-MiniLM-L-6-v2
    │
    ▼ (상위 top_n=5)
RetrievalResult
```

**한국어 대응**: 공백 토크나이저 + 2-gram 문자 bigram 보강으로 CJK 검색 품질 향상.

### 3.4 CP4 — 평가 (`cp4_evaluator/judge.py`)

#### 4개 핵심 메트릭

| 메트릭 | 측정 대상 | SLA |
|--------|-----------|-----|
| `faithfulness` | 답변이 컨텍스트에 근거하는가 (환각 탐지) | 0.80 |
| `answer_relevance` | 답변이 질문과 관련이 있는가 | 0.75 |
| `context_precision` | 검색된 청크 중 실제 관련 있는 비율 | 0.70 |
| `context_recall` | 필요한 정보가 컨텍스트에 포함된 비율 | 0.70 |

#### 신뢰성: N-Sample Sampling

```
단일 질의 평가
    │
    ├─ Sample 1 (temperature=0.4)
    ├─ Sample 2
    └─ Sample 3
         │
         ▼
    median(scores)         → 최종 점수 (이상치 강건)
    pstdev(scores) > 0.2   → is_low_confidence = True
```

#### 고급 기법 (선택적 활성화)

```
faithfulness: claim 분해(RAGAS) → NLI 판정 → claim별 supported/unsupported
ensemble: OpenAI + Anthropic 교차 평가 → 불일치 > 0.25 → 메타 Judge 에스컬레이션
calibration: 앵커 기반 편향 보정 + G-Eval logprob 기대점수
nugget: 질문 → 핵심 nugget 추출 → 컨텍스트 매칭 (GT-free recall)
```

---

### 3.5 CP5 — 집계 (`cp5_aggregator/aggregator.py`)

```
입력: list[EvaluationRecord]
출력: AuditSummary

집계 통계:
  - mean, median, P10, P90 (per metric)
  - sla_pass_rate = (SLA 통과 수) / 전체
  - flagged_call_ids: 1개라도 SLA 미달 메트릭이 있는 call_id

선택 기능:
  - 부트스트랩 CI (1000 샘플, 95% 신뢰구간)
  - 진단 분포 {retrieval_failure, generation_hallucination, both, healthy}
  - 휴먼 검수 큐 선정 (active sampling)
  - 메타평가 (골든셋 대비 Spearman ρ, Cohen κ, MAE)
```

### 3.6 CP6 — 리포트 (`cp6_reporter/`)

| 파일 | 기능 |
|------|------|
| `reporter.py` | HTML 대시보드 + JSON 아카이브 생성 |
| `regression.py` | 직전 배치 대비 회귀 감지 (고정 임계값 or 순열검정) |
| `notifier.py` | Slack webhook 알림 (회귀·SLA 미달 시) |

**HTML 리포트 색상 기준**: 초록(≥0.9) · 노란(≥0.7) · 빨강(<0.7)

## 5. 저장소 구조

### 5.1 SQLite 스키마 (`data/results/autoaudit.db`)

```sql
-- 평가 결과 (핵심 테이블)
CREATE TABLE evaluations (
    eval_id TEXT PRIMARY KEY,
    run_id  TEXT,
    tenant_id TEXT,
    call_id TEXT,
    conversation_id TEXT,
    subscriber_id TEXT,
    level TEXT,             -- retrieval / turn / session
    query TEXT,
    generated_answer TEXT,
    scores_json TEXT,       -- JSON: list[MetricScore]
    review_status TEXT,     -- pending / approved / overridden / skipped
    human_scores_json TEXT,
    ...
);

-- 배치 요약
CREATE TABLE summaries (
    run_id TEXT PRIMARY KEY,
    total_calls INT,
    total_evaluations INT,
    metrics_json TEXT,
    flagged_call_ids_json TEXT,
    ...
);

-- 대화 세션
CREATE TABLE conversations (
    conversation_id TEXT PRIMARY KEY,
    tenant_id TEXT,
    subscriber_id TEXT,
    is_multiturn BOOL,
    turn_count INT,
    ...
);
```

## 6. Provider 추상화

```python
class LLMProvider (ABC):
    async def complete(prompt, temperature, max_tokens) → str
    async def embed(text) → list[float]

구현체:
  OpenAIProvider    → gpt-4o + text-embedding-3-large
  AnthropicProvider → claude-sonnet-4-5
  AzureProvider     → Azure OpenAI 엔드포인트
  GeminiProvider    → gemini-2.5-pro
  MockProvider      → 결정적 해시 기반 응답 (API 키 불필요)
```

`create_provider()`가 `config/settings.yaml`의 `llm.provider` 값으로 구현체 선택.
