## 3. 파이프라인 단계별 설계

### 3.1 CP1 — 전처리 (`cp1_preprocessing/parser.py`)

```
입력: data/raw/ (txt | json | csv 콜 로그 파일)
출력: list[CallLog]

CallLog {
  call_id, subscriber_id, started_at, ended_at,
  turns: list[ConversationTurn {turn_id, role: user|bot|system, content, timestamp}],
  metadata: dict
}
```

**포맷별 파서 상세:**

| 포맷 | 메서드 | 헤더/구조 |
|------|--------|---------|
| JSON | `_parse_json()` | `{"call_id":..., "turns":[{"role":"user","content":"..."}]}` |
| CSV | `_parse_csv()` | 헤더: `call_id, subscriber_id, timestamp, role, content` |
| TXT | `_parse_txt()` | 1행: `[CALL_ID: C001] [SUBSCRIBER: S001]`<br>이후: `[timestamp] USER: content` |

**공통 필터**: 턴 content 길이 < `min_turn_length`(기본 5) → 제외.  
누락 메타데이터는 경고 후 기본값(파일명 → call_id, "unknown" → subscriber_id) 처리.  
결과를 `Tracer`로 `data/results/run_{id}/cp1_call_logs_{ts}.json`에 저장.

### 3.2 CP2 — 지식 베이스 (`cp2_knowledge_base/`)

#### 청킹 전략: Parent-Child Chunking

```
CallLog.turns → _build_full_text() → "[USER] 질문\n[BOT] 답변\n..."
                                              │
                        ┌─────────────────────┘
                        │
              슬라이딩 윈도우 (단어 단위)
                        │
           Parent Chunk (1000 words, overlap 50)
                        │
             재분할 (슬라이딩 윈도우)
                        │
           Child Chunk (200 words, overlap 50)
           └── parent_chunk_id 참조 저장
```

`_build_full_text()`: 각 턴을 `[ROLE] content` 형식으로 줄바꿈 연결.  
`_split_text()`: `text.split()` 단어 단위, `start += chunk_size - overlap` 슬라이딩.  
`_approx_tokens()`: 단어 수로 토큰 수 근사.

**설계 근거**: Child 단위 검색으로 Precision 최적화, 컨텍스트 제공 시 Parent로 확장해 Recall 확보.

#### 인덱싱 (`indexer.py`)

```
인덱싱 대상: Child 청크만 (Parent는 메타데이터로만 참조)
임베딩 모델: text-embedding-3-large (3072차원)
유사도: cosine (HNSW, hnsw:space=cosine)
동시성: concurrency=10 (gather_with_concurrency)
저장소: ChromaDB PersistentClient (data/chroma_db/)
Mock 모드: InMemoryVectorStore (chromadb 미사용)
```

### 3.3 CP3 — 검색 (`cp3_retrieval/retriever.py`)

#### HybridRetriever 전체 파이프라인

```
질의(Query)
    │
    ├─① HyDE (Hypothetical Document Embeddings)
    │      LLM으로 가상 이상적 답변 생성 (temperature=0.3)
    │      → 실제 문서에 더 가까운 임베딩 공간
    │
    ├─② Multi-Query
    │      LLM으로 3개 변형 질의 생성 (temperature=0.5)
    │
    ▼
[질의 pool: 원본 + HyDE + Multi-Query(3개) = 최대 5개]
    │
    ├─ Dense Search: ChromaDB cosine 유사도
    └─ BM25 Search:  rank-bm25 Okapi / 한국어 bigram 보강 토크나이저
    │
    ▼
③ Weighted Reciprocal Rank Fusion
   score += weight / (rrf_k(60) + rank)
   dense_weight=0.7, bm25_weight=0.3
    │
    ▼ (상위 top_k=20 후보)
④ Cross-Encoder Reranking
   모델: cross-encoder/ms-marco-MiniLM-L-6-v2
   Mock: 토큰 중첩 점수 (sentence-transformers 미사용)
    │
    ▼ (상위 top_n=5)
RetrievalResult {query, hyde_query, sub_queries, contexts}
```

**한국어 대응 토크나이저** (`_tokenize`):
```python
words = text.lower().split()                                   # 공백 분리
bigrams = [text[i:i+2] for i in range(len(text)-1) if ...]   # 2-gram 문자 보강
return words + bigrams
```

**BM25 인덱스 구축**: `_ensure_bm25()` — 최초 호출 시 ChromaDB 전체 Child 문서로 1회 구축, 이후 캐시.

### 3.4 CP3.5 — QA 추출 (`cp4_evaluator/qa_builder.py`)

```
CallLog.turns 순회
    │
    ├─ 연속 User 발화 → " ".join() 병합 → question
    ├─ 연속 Bot 발화  → " ".join() 병합 → bot_answer
    │
    ├─ 필터 조건:
    │   len(question) < min_question_len(4) → 제외
    │   len(answer) < min_answer_len(4) → 제외
    │   answer가 스킵 접두사로 시작 AND len < 20 → 제외
    │
    └─ QAPair {qa_id(uuid4), call_id, subscriber_id, question, bot_answer, turn_index}
    
    ↓ attach_retrieval() - concurrency=5
    
    QAPair.retrieval_result = await retriever.retrieve(question)
```

스킵 접두사(`skip_answer_prefixes`): `["안녕하세요", "감사합니다", "네,", "잠시만"]`  
※ 길이가 20 이상이면 스킵하지 않음 (의미 있는 답변 보존).

### 3.5 CP4 — 평가 (`cp4_evaluator/judge.py`)

#### 메트릭 평가 분기 로직

```
_evaluate_metric(metric, query, answer, contexts_text)
    │
    ├─ metric=="context_recall" AND nugget.enabled
    │   → NuggetRecallEvaluator (질문 → nugget 추출 → 컨텍스트 매칭)
    │
    ├─ metric=="faithfulness" AND use_claim_faithfulness(True)
    │   → FaithfulnessEvaluator (claim 추출 → NLI 판정 → 비율 점수)
    │
    ├─ ensemble.enabled
    │   → EnsembleJudge (다중 Provider 병렬 → 집계 or 에스컬레이션)
    │
    ├─ calibration.enabled
    │   → JudgeCalibrator (앵커+길이정규화 데코레이션 → G-Eval)
    │
    └─ 기본: N-샘플 중앙값 집계
         n_samples=3, sample_temperature=0.4
         median(scores) → final_score
         confidence = max(0.0, 1.0 - pstdev(scores) / 0.5)
         is_low_confidence = pstdev(scores) > 0.2

→ routing.enabled AND is_low_confidence
    → extra_samples_on_low_conf(4) 추가 샘플링 + escalated=True
```

#### FaithfulnessEvaluator (RAGAS claim NLI)

```
답변(answer)
    │
    ①  LLM: claim 추출 (max 10개)
       프롬프트 → {"claims": ["주장1", "주장2", ...]}
    │
    ②  LLM: NLI 판정 (한 번에 전체 claim 목록)
       컨텍스트 vs 각 claim → supported | unsupported | contradicted
    │
    ③  점수 = supported 수 / 전체 claim 수
       claim 없음 → 1.0 (환각 위험 없음)
       판정 누락 claim → 보수적 "unsupported" 처리
```

#### N-샘플 집계 알고리즘

```python
sample_scores = [score1, score2, score3]  # temperature=0.4로 3회 호출
final_score   = statistics.median(sample_scores)        # 이상치 강건
confidence    = max(0.0, 1.0 - statistics.pstdev(sample_scores) / 0.5)
is_low_conf   = statistics.pstdev(sample_scores) > 0.2
# 중앙값에 가장 가까운 샘플의 reasoning 채택
best = min(samples, key=lambda s: abs(s.score - final_score))
```

#### EnsembleJudge 상세

```
providers = ["openai", "anthropic"]  (기본값)
    │
    ├─ available = len(providers) >= 2  (미만이면 단일 폴백)
    │
    ├─ 각 provider 병렬 평가 → per_provider={provider: score}
    │
    └─ std = pstdev(scores)
         std ≤ 0.25: mean/median 집계 (aggregation 설정에 따라)
         std > 0.25: escalate_provider로 메타 판정 (에스컬레이션)
                     에스컬레이션 실패 시 집계로 폴백
```

#### JudgeCalibrator (G-Eval)

```
decorate_prompt():
    [척도 기준 앵커] 삽입 (use_anchors=True)
    [길이정규화 지시문] 추가 (length_normalize=True)

score():
    g_eval_logprobs=True AND provider.complete_with_logprobs 지원
        → 토큰 분포 기댓값: Σ(score×prob) / Σ(prob)
        → 미지원 시 None 반환 → 다중샘플 기댓값으로 graceful degrade

    g_eval_logprobs=False (기본)
        → temperature=0.6으로 3회 샘플링 → mean(scores)
```

### 3.6 CP5 — 집계 (`cp5_aggregator/aggregator.py`)

```python
# 메트릭별 통계
mean   = statistics.mean(scores)
median = statistics.median(scores)
p10    = _percentile(scores, 10)   # 보간법 (lo + (hi-lo) * frac)
p90    = _percentile(scores, 90)

# 부트스트랩 CI (statistics.enabled=True)
ci = bootstrap_ci(scores, n_samples=1000, confidence=0.95, seed=42)
# percentile 방식: mean[lo_idx ~ hi_idx] 추출

# SLA 플래깅 (1개 메트릭이라도 임계 미달이면)
for rec in records:
    for ms in rec.scores:
        if ms.score < sla.get(ms.metric, 0.7):
            flagged.add(rec.call_id); break
return sorted(flagged)  # 정렬된 리스트

# 선택 기능 (options별 분기)
diagnosis  → RetrievalGenerationDiagnoser.diagnose_all(records)
routing    → EvaluationRouter.select_for_human_review(records)
meta_eval  → MetaEvaluator.evaluate(records)
```

### 3.7 CP6 — 리포트 (`cp6_reporter/`)

#### `reporter.py`

- HTML: 색상 코딩 (초록 ≥0.9, 노란 ≥0.7, 빨강 <0.7). `AuditSummary.model_dump()` 직접 직렬화.
- JSON: `summary.model_dump(mode="json")` + `[r.model_dump(mode="json") for r in records]`

#### `regression.py`

| 함수 | 방식 | 사용 조건 |
|------|------|-----------|
| `detect_regression(current, previous)` | 메트릭 평균 하락 > `regression_threshold`(0.05) | statistics 옵션 OFF 또는 이전 점수 없음 |
| `detect_regression_significant(cur_scores, prev_scores)` | 순열검정(1000회) p-value < alpha(0.05) | statistics 옵션 ON + 이전 원시 점수 있음 |

#### `notifier.py`

```python
class SlackNotifier:
    def send(self, text: str) -> bool:
        # 외부 HTTP 라이브러리 없음 — stdlib urllib.request만 사용
        payload = json.dumps({"text": text}).encode("utf-8")
        req = urllib.request.Request(webhook_url, data=payload, ...)
        with urllib.request.urlopen(req, timeout=10) as resp:
            return resp.status == 200
```

webhook_url 미설정 시 발송 생략 (enabled=False).

## 6. Provider 추상화

```python
@runtime_checkable
class LLMProvider(Protocol):
    async def complete(
        self, prompt: str, *, system: str | None = None,
        temperature: float = 0.0, max_tokens: int = 2048, json_mode: bool = False,
    ) -> str: ...
    
    async def embed(self, text: str) -> list[float]: ...
```

`create_provider(cost_tracker)` 팩토리:
1. `AUTOAUDIT_MOCK=1` 환경변수 → `MockProvider` 강제
2. `settings.yaml llm.provider` 값으로 구현체 선택
3. 모든 구현체에 `cost_tracker` 주입 → 비용 누적 공유

**재시도 전략 (`_is_transient`):**
```python
# 재시도 대상 (tenacity AsyncRetrying, 지수 백오프 1~20초, max 4회)
HTTPStatus: 408, 409, 429, 500, 502, 503, 504
Exception name: ratelimit, timeout, apiconnection, internalserver, serviceunavailable

# 즉시 실패 (재시도 없음)
HTTPStatus: 400 (Bad Request — 수정 없이 재시도해도 의미 없음)
```

```
AUTOAUDIT_MOCK=1
    │
    ├── MockProvider
    │     ├── complete(prompt) → 프롬프트 패턴 인식 분기
    │     │     ├── "원자적 주장(claim)" → _claims()  JSON
    │     │     ├── "지지되는지 판정"    → _verdicts() JSON
    │     │     ├── "핵심 정보 조각"     → _nuggets()  JSON

    │     │     ├── "이상적인 답변"      → HyDE 텍스트
    │     │     └── json_mode=True       → _metric_score()
    │     │           토큰 중첩 기반 0.5~1.0 점수
    │     │
    │     └── embed(text) → deterministic_embedding(text, dim=64)
    │           토큰별 MD5 해시 → 64차원 벡터 버킷 → L2 정규화
    │
    ├── InMemoryVectorStore (chromadb 완전 대체)
    │     ├── upsert/add: 리스트 append 또는 id 기반 갱신
    │     ├── get: {ids, documents, metadatas}
    │     └── query: cosine 유사도 정렬 → top-k
    │           _cosine(): 내적 / (norm_a * norm_b)
    │
    └── HybridRetriever (mock_mode=True)
          ├── _SimpleBM25: stdlib만 사용 (rank-bm25, numpy 미사용)
          │     IDF = log(1 + (n-f+0.5)/(f+0.5))
          │     BM25 = Σ IDF * (tf*(k1+1)) / (tf + k1*(1-b+b*dl/avgdl))
          └── _rerank(): 토큰 중첩 점수 (sentence-transformers 미사용)
```

**결정적 보장**: 동일 입력 텍스트 → 동일 MD5 해시 → 동일 임베딩 벡터 → 동일 평가 점수.

## 9. 비동기 처리 아키텍처

```python
# gather_with_concurrency (async_utils.py)
async def gather_with_concurrency(coros, concurrency=5):
    semaphore = asyncio.Semaphore(concurrency)
    async def bounded(coro):
        async with semaphore:
            return await coro
    return list(await asyncio.gather(*[bounded(c) for c in coros]))

# 단계별 동시성 설정
CP2 임베딩:    concurrency=10
CP3 QA 검색:  concurrency=5  (cp3.retrieval_concurrency)
CP4 평가:     concurrency=5  (cp4.concurrency)
CP4 N샘플:    concurrency=n_samples (메트릭 내부)
CP4 메트릭:   concurrency=cp4.concurrency (메트릭 간)
```
