## 3. 파이프라인 단계별 설계

### 3.1 CP1 — 전처리 (`cp1_preprocessing/parser.py`)

**포맷별 파서:**

| 포맷 | 정확한 형식 |
|------|------------|
| JSON | `{"call_id":"...", "turns":[{"role":"user","content":"..."}]}` |
| CSV | 헤더: `call_id, subscriber_id, timestamp, role, content` (turn_id 없음) |
| TXT | 헤더행: `[CALL_ID: C001] [SUBSCRIBER: SUB_01]`<br>턴행: `[timestamp] USER|BOT|SYSTEM: content` |

결과: `data/results/{run_id}/cp1_call_logs_{ts}.json` (Tracer 저장)

---

### 3.2 CP2 — 지식 베이스 (`cp2_knowledge_base/`)

```
CallLog.turns → _build_full_text()
             → "[USER] 질문\n[BOT] 답변\n..."

슬라이딩 윈도우:
  Parent: 1000 words, overlap 50
  Child:  200 words, overlap 50
  
Child만 ChromaDB에 인덱싱 (concurrency=10 임베딩)
```

---

### 3.3 CP3 — 검색 (`cp3_retrieval/retriever.py`)

```
질의 → HyDE(temp=0.3) + Multi-Query(3개, temp=0.5)
모든 질의(최대 5개) → Dense(ChromaDB cosine) + BM25
→ Weighted RRF: score += weight/(rrf_k+rank)
  dense_weight=0.7, bm25_weight=0.3, rrf_k=60
→ top_k=20 후보 → Cross-Encoder Rerank → top_n=5
```

---

### 3.4 CP3.5 — QA 추출 (`cp4_evaluator/qa_builder.py`)

연속 User/Bot 발화 병합 + trivial 필터(스킵접두사 && len<20).  
`attach_retrieval()`: concurrency=5 병렬 검색.

---

### 3.5 CP4 — 평가 (`cp4_evaluator/`)

#### 메트릭 평가 분기

```
1. context_recall + nugget.enabled → NuggetRecallEvaluator
   → LLM으로 nugget 추출(max 8) → 각 nugget 컨텍스트 매칭
   → recall = found/total, 반환: (MetricScore, list[Nugget])

2. faithfulness + use_claim_decomposition(True) → FaithfulnessEvaluator
   → claim 추출(max 10) → NLI 판정 → score = supported/total
   → claim 없음: score=1.0 / 판정 누락: 보수적 unsupported

3. ensemble.enabled → EnsembleJudge
   → 2개 이상 provider 병렬 → std > 0.25: 에스컬레이션
   → available < 2: 단일 폴백

4. calibration.enabled → JudgeCalibrator
   → 앵커(_ANCHOR_BLOCK) + 길이정규화(_LENGTH_NORM) 삽입
   → G-Eval: logprob 기댓값(지원시) or 3샘플 기댓값

5. 기본: N-샘플(n=3, temp=0.4) → 중앙값
   confidence = max(0.0, 1.0 - pstdev/0.5)
   is_low_confidence = pstdev > 0.2
   → routing.enabled && is_low_confidence: 4샘플 추가 에스컬레이션
```

#### 세션 평가 (`session_eval.py`)

| 메트릭 | 측정 방법 |
|--------|---------|
| `resolution` | LLM 판정: resolved여부 + resolution_score |
| `efficiency` | LLM 판정: efficiency_score |
| `escalation_handling` | LLM: escalation_needed → 0.0/1.0 |
| `multiturn_consistency` | DomainMetricsEvaluator 재사용 |
| `gt_similarity` | 마지막 봇 답변 vs GT 임베딩 cosine (optional) |

대화 포맷: `고객: ... \n 콜봇: ...` (role → 한국어 매핑)

#### 도메인 메트릭 (`domain_metrics.py`)

**PII 탐지 (정규식 기반, LLM 불필요):**

| PII 유형 | 패턴 |
|---------|------|
| 주민등록번호 | `\d{6}-[1-4]\d{6}` |
| 카드번호 | `\d{4}[-]\d{4}[-]\d{4}[-]\d{4}` (16자리) |
| 전화번호 | `01[016789][- ]?\d{3,4}[- ]?\d{4}` |
| 계좌번호 | `\d{2,6}-\d{2,6}-\d{2,6}` |

탐지 우선순위: 주민번호 → 카드번호 → 전화번호 → 계좌번호.  
`consumed` 구간으로 중복 오분류 방지(전화번호 → 계좌번호 오탐 방지).  
PII 탐지 시 즉시 score=0.0 (LLM 호출 생략, 비용 절감).  
PII 없을 시 2차 LLM 컴플라이언스 판정.

### 3.6 CP5 — 집계 (`cp5_aggregator/`)

```python
# 통계 집계
mean, median, P10, P90 per metric
bootstrap_ci(n=1000, confidence=0.95, seed=42)  # stdlib random

# SLA 플래그
1개 메트릭이라도 < threshold → flagged
return sorted(flagged)  # 정렬 반환

# 선택 기능
diagnosis  → RetrievalGenerationDiagnoser.diagnose_all(records)
            → rec.diagnosis = DiagnosisVerdict (side effect)
routing    → EvaluationRouter.select_for_human_review(records)
            → rec.needs_human_review = True (side effect)
meta_eval  → MetaEvaluator(JSONL 골든셋).evaluate(records)
```

**`statistics_ext.py` 추가 함수:**

| 함수 | 용도 |
|------|------|
| `bootstrap_ci()` | 부트스트랩 CI (percentile, seed=42 결정적) |
| `paired_permutation_test()` | 순열검정 p-value (회귀 유의성) |
| `ppi_mean()` | PPI 추정: clf_mean + bootstrap_ci(rectifiers).mean |

## 5. SQLite 스키마 상세 (`core/store.py`)

### 5.1 테이블 구조 (5개)

```sql
-- 배치 실행 요약
CREATE TABLE runs (
    run_id TEXT PRIMARY KEY,
    generated_at TEXT,          -- ISO 8601
    total_calls INTEGER,
    total_evaluations INTEGER,
    flagged_count INTEGER,
    flagged_json TEXT            -- JSON: list[str] flagged call_ids
);

-- 평가 레코드 (한 행 = 한 QA 쌍)
CREATE TABLE evaluations (
    eval_id TEXT PRIMARY KEY,
    run_id TEXT,
    qa_id TEXT,
    call_id TEXT,
    tenant_id TEXT DEFAULT 'default',
    conversation_id TEXT,
    subscriber_id TEXT,
    level TEXT DEFAULT 'turn',   -- retrieval | turn | session
    turn_index INTEGER,
    query TEXT,
    generated_answer TEXT,
    retrieval_json TEXT,         -- RetrievalResult model_dump JSON
    ground_truth TEXT,
    judge_provider TEXT,
    judge_model TEXT,
    evaluated_at TEXT,
    review_status TEXT DEFAULT 'pending',  -- pending|approved|overridden|skipped
    human_scores_json TEXT,      -- JSON: {metric: score}
    human_label_json TEXT,       -- JSON: list[str]
    human_comment TEXT,
    reviewer TEXT,
    reviewed_at TEXT
);

-- 메트릭별 점수 (별도 행 — SQL 필터 최적화)
CREATE TABLE scores (
    eval_id TEXT,
    run_id TEXT,
    metric TEXT,
    score REAL,
    confidence REAL,
    is_low_confidence INTEGER,   -- 0/1
    reasoning TEXT,
    grounding_json TEXT,         -- JSON: list[str] chunk_ids
    PRIMARY KEY (eval_id, metric)
);

-- 배치별 메트릭 통계 집계
CREATE TABLE metric_summary (
    run_id TEXT,
    metric TEXT,
    mean REAL, median REAL, p10 REAL, p90 REAL,
    below_sla_count INTEGER,
    total_count INTEGER,
    sla_pass_rate REAL,
    PRIMARY KEY (run_id, metric)
);

-- 대화 세션 원문 (turns_json)
CREATE TABLE conversations (
    conversation_id TEXT PRIMARY KEY,
    tenant_id TEXT DEFAULT 'default',
    subscriber_id TEXT,
    is_multiturn INTEGER DEFAULT 0,  -- 봇 답변 2개 이상이면 1
    turn_count INTEGER DEFAULT 0,
    turns_json TEXT,                  -- JSON: list[{role, content}]
    started_at TEXT,
    metadata_json TEXT
);
```

### 5.3 WAL 모드 (동시 읽기)

```python
def _connect(self) -> sqlite3.Connection:
    conn = sqlite3.connect(self.db_path)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA journal_mode=WAL;")       # 동시 읽기 허용
    conn.execute("PRAGMA synchronous=NORMAL;")     # 성능/내구성 균형
    return conn
```
