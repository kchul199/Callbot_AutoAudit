### 3.3 CP3 — 검색 (`cp3_retrieval/retriever.py`)

```
질의 → HyDE(temp=0.3) + Multi-Query(3개, temp=0.5)
모든 질의(최대 5개) → Dense(ChromaDB cosine) + BM25
→ Weighted RRF: score += weight/(rrf_k+rank)
  dense_weight=0.7, bm25_weight=0.3, rrf_k=60
→ top_k=20 후보 → Cross-Encoder Rerank → top_n=5
```

### 3.5 CP4 — 평가 (`cp4_evaluator/`)

#### 메트릭 평가 분기

```
0. abstention.enabled (evaluate 진입 시 1회 판정, 메트릭 간 공유)
   → 답변이 거절/모름(정규식) AND 거절 정당(LLM) AND metric ∈ exempt_metrics
   → 즉시 exempt_score 반환 (method=abstention_exempt, abstention=True)

1. context_recall + nugget.enabled → NuggetRecallEvaluator
   → LLM으로 nugget 추출(max 8) → 각 nugget 컨텍스트 매칭
   → recall = found/total, 반환: (MetricScore, list[Nugget])

2. faithfulness + use_claim_decomposition(True) → FaithfulnessEvaluator
   → claim 추출(max 10) → NLI 판정 → score = supported/total
   → claim 없음: score=1.0 / 판정 누락: 보수적 unsupported
   → numeric_guard.enabled: 수치·날짜 결정적 대조 후 충돌 수만큼 감점 (numeric_flags)

3. ensemble.enabled → EnsembleJudge
   → 2개 이상 provider 병렬 → std > 0.25: 에스컬레이션
   → available < 2: 단일 폴백

4. calibration.enabled → JudgeCalibrator
   → 앵커(_ANCHOR_BLOCK) + 길이정규화(_LENGTH_NORM) 삽입
   → G-Eval: logprob 기댓값(지원시) or 3샘플 기댓값

5. 기본: N-샘플(n=3, temp=0.4) → 중앙값
   cot.enabled && metric in cot.metrics → CoT 프롬프트 사용 (method=cot)
   answer_relevance + ground_truth + reference_guided → 모범답안 주입 프롬프트(②)
   context_injection.enabled && metric ∈ metrics → 직전 N턴 맥락 prepend(③)
   confidence = max(0.0, 1.0 - pstdev/0.5)
   is_low_confidence = pstdev > 0.2
   → routing.enabled && is_low_confidence: 4샘플 추가 에스컬레이션

6. reverse.enabled && metric in reverse.metrics → 역방향 검증 후처리
   (위 1~5에서 산출된 forward_score에 역방향 점수 결합)

7. correctness.enabled && ground_truth → answer_correctness 메트릭 추가(①)
   → claim F1(TP/FP/FN) × w_f1 + 의미 유사도 × w_sim

[CP4 종료 후] auto_calibration.enabled → 골든셋 보정맵 학습 → 점수 교정 + SLA 자동튜닝(⑦)
```

#### CoT 강제 평가 (Chain-of-Thought)

```
대상 메트릭: answer_relevance / context_precision / context_recall
  (faithfulness는 claim NLI가 이미 CoT 역할)

기존 프롬프트: "0~1 점수를 매겨라" → LLM이 점수 먼저 결정 후 근거 역생성 (편향)

CoT 프롬프트 구조 (예: answer_relevance):
  Step 1 — 질문 의도 파악
  Step 2 — 답변 항목 나열
  Step 3 — 누락/이탈 분석
  Step 4 — 최종 점수 산출 (위 분석 종합)

출력: step별 필드 + score → _parse_cot_score()가 cot_steps[]에 기록
비용: 추가 LLM 호출 없음 (프롬프트 구조만 변경) → 토큰만 소폭 증가
저장: MetricScore.cot_steps (Evidence View에서 단계별 추론 표시)
```

#### 역방향 검증 (Reverse Verification)

```
대상 메트릭: faithfulness / answer_relevance

순방향(forward): 기존 평가 (답변→컨텍스트 지지 / 답변→질문 응답)
역방향(backward):
  faithfulness     → 컨텍스트로부터 답변을 도출할 수 있는가 (_REVERSE_FAITHFULNESS_PROMPT)
  answer_relevance → 답변만 보고 원래 질문을 역추론할 수 있는가 (_REVERSE_ANSWER_RELEVANCE_PROMPT)

결합 공식 (_apply_reverse):
  final_score   = forward × weight_forward(0.6) + reverse × weight_reverse(0.4)
  consistency   = |forward - reverse|
  is_low_confidence = consistency > inconsistency_threshold(0.25) OR forward.is_low_confidence

효과: 한 방향에서 놓친 환각을 다른 방향이 포착 → False Negative 환각 탐지율↑
비용: 메트릭당 LLM 호출 1회 추가 (순방향 + 역방향 = 2×)
저장: forward_score / reverse_score / consistency_score (방향 불일치 추적)
method: "reverse" (단독) 또는 "cot_reverse" (CoT와 결합 시)
```

#### 정답성 + 참조 기반 채점 (`correctness.py`) ① ②

```
대상: ground_truth(정답)가 있는 QAPair (없으면 메트릭 미생성)

answer_correctness = claim F1 × weight_f1(0.75) + 의미유사도 × weight_similarity(0.25)
  claim F1: LLM이 [정답] vs [답변] 진술을 TP/FP/FN 분류 → 2·TP/(2·TP+FP+FN)
    TP=양쪽 일치  FP=답변에만(틀림/불필요)  FN=정답에만(누락)
  의미유사도: 답변·정답 임베딩 코사인
저장: correctness_f1 / correctness_sim, grounding_chunks에 FN/FP 진술 기록

참조 기반 채점(②): answer_relevance를 _COT_ANSWER_RELEVANCE_REF_PROMPT로 평가
  → 프롬프트에 [모범답안] 주입, 모범답안 대비 누락/이탈 분석 후 채점
  → judge-사람 일치도 향상 (출력 스키마는 CoT와 동일 → 동일 파서 재사용)
효과: faithfulness(컨텍스트 충실도)가 못 잡는 '충실하지만 틀린 답변'을 직접 포착
```

#### 적정 거절 + 수치 가드 (`abstention.py` / `numeric_guard.py`) ④ ⑤

```
적정 거절(④): evaluate() 진입 시 1회 판정해 메트릭 간 공유 (중복 LLM 호출 방지)
  is_abstention: 거절/모름 정규식(_REFUSAL_RE) — LLM 불필요
  appropriate: 거절 시에만 LLM 1회 — 컨텍스트에 근거 부재면 정당
  정당 → exempt_metrics(faithfulness/answer_relevance)에 exempt_score(1.0) 부여
       method=abstention_exempt, abstention=True → 정당한 거절의 거짓 실패 제거

수치 가드(⑤): faithfulness 후처리 (결정적, LLM 호출 0)
  답변/컨텍스트에서 숫자·단위·날짜 정규식 추출 → 정규화 집합 대조
  컨텍스트에 없는 답변 수치 = 충돌 → score -= penalty_per_conflict(0.3) × 충돌수
  numeric_flags에 충돌 수치 기록, is_low_confidence=True
효과: LLM claim NLI가 놓치는 '월 3만→3만5천' 같은 수치 환각을 결정적으로 포착
```

#### 휴먼 정합 자동 보정 (`auto_calibration.py`) ⑦

```
meta_eval(측정: spearman/kappa/mae)을 '교정'으로 확장. CP4 종료 후 1회.

fit: 골든셋(qa_id,metric→human) × records(judge) 매칭 → 메트릭별 보정맵 학습
  isotonic: PAVA 단조 보정 + 선형보간 (비모수)
  platt:    sigmoid(a·x+b) 경사하강
  linear:   최소제곱 y=a·x+b
  min_samples(10) 미만 메트릭은 보정 생략
apply: 모든 점수에 보정맵 적용, 원점수는 calibrated_from에 보존
SLA 자동튜닝: judge 임계를 사람 합격(human≥0.5) 예측 F1 최대화 지점으로 탐색
stdlib만 사용 (numpy/scipy 미의존)
효과: judge 점수를 사람 척도로 끌어당겨 SLA 판정을 사람-정렬 + 정확도 폐루프 개선
```

#### 도메인 메트릭 (`domain_metrics.py`)

**PII 탐지 (정규식 기반, LLM 불필요):**

| PII 유형 | 패턴 |
|---------|------|
| 주민등록번호 | `\d{6}-[1-4]\d{6}` |
| 카드번호 | `\d{4}[-]\d{4}[-]\d{4}[-]\d{4}` (16자리) |
| 전화번호 | `01[016789][- ]?\d{3,4}[- ]?\d{4}` |
| 계좌번호 | `\d{2,6}-\d{2,6}-\d{2,6}` |

탐지 우선순위: 주민번호 → 카드번호 → 전화번호 → 계좌번호.  
`consumed` 구간으로 중복 오분류 방지(전화번호 → 계좌번호 오탐 방지).  
PII 탐지 시 즉시 score=0.0 (LLM 호출 생략, 비용 절감).  
PII 없을 시 2차 LLM 컴플라이언스 판정.

### 3.6 CP5 — 집계 (`cp5_aggregator/`)

```python
# 통계 집계
mean, median, P10, P90 per metric
bootstrap_ci(n=1000, confidence=0.95, seed=42)  # stdlib random

# SLA 플래그
1개 메트릭이라도 < threshold → flagged
return sorted(flagged)  # 정렬 반환

# 선택 기능
diagnosis  → RetrievalGenerationDiagnoser.diagnose_all(records)
            → rec.diagnosis = DiagnosisVerdict (side effect)
routing    → EvaluationRouter.select_for_human_review(records)
            → rec.needs_human_review = True (side effect)
meta_eval  → MetaEvaluator(JSONL 골든셋).evaluate(records)
```

**`statistics_ext.py` 추가 함수:**

| 함수 | 용도 |
|------|------|
| `bootstrap_ci()` | 부트스트랩 CI (percentile, seed=42 결정적) |
| `paired_permutation_test()` | 순열검정 p-value (회귀 유의성) |
| `ppi_mean()` | PPI 추정: clf_mean + bootstrap_ci(rectifiers).mean |
