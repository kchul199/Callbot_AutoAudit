> **버전** v1.1 | **작성일** 2026-06-03 | **상태** 완료(구현 완료 기준)

## 1. 제품 개요

### 1.1 배경 및 목적

SaaS형 생성형 콜봇은 가입자(고객사)가 업로드한 지식 데이터를 RAG(Retrieval-Augmented Generation) 시스템으로 색인하고, 최종 사용자(가입자의 고객)의 문의에 LLM이 답변을 생성한다. 이 과정에서 다음 문제가 발생한다.

| 문제 | 영향 |
|------|------|
| LLM 환각(Hallucination) — 지식 베이스에 없는 내용을 답변 | 고객 신뢰 손상, 민원 |
| 검색 실패 — 관련 문서가 있어도 RAG가 찾지 못함 | 답변 품질 저하 |
| Ground Truth 부재 — 정답 없이 품질을 객관적으로 측정 불가 | 지표 부재, 개선 방향 불명확 |
| 멀티테넌트 운영 — 가입자별 품질 현황을 개별 모니터링 불가 | 운영 효율 저하 |

**CallBot AutoAudit**은 위 문제를 해결하기 위한 **RAG 품질 자동 감사 파이프라인 + 관리 콘솔**이다.

- Ground Truth 없이도 신뢰할 수 있는 품질 지표 산출 (LLM-as-a-Judge)
- 자동 평가 후 **인간 검수 → Final Score 확정** 워크플로우
- 가입자별 완전 격리된 멀티테넌트 구조

---

### 1.2 제품 범위

```
범위 IN:
  - CP1~CP6 평가 파이프라인 (콜 로그 → 품질 리포트)
  - Admin Console (웹 대시보드, Vite + React)
  - FastAPI REST API 백엔드
  - 로컬 개발 Mock 모드 (API 키·GPU 불필요)

범위 OUT:
  - 콜봇 자체(답변 생성) 구현
  - 가입자 온보딩 / 결제 시스템
  - 콜 로그 수집 에이전트
  - 실시간 스트리밍 평가
```

## 2. 핵심 도메인 모델

### 2.1 용어 정의

| 용어 | 정의 |
|------|------|
| **Tenant** | 콜봇을 운영하는 가입자(고객사). KB·대화이력·평가가 테넌트 단위로 격리 |
| **Knowledge Base (KB)** | 테넌트가 업로드한 지식 데이터로 만든 RAG 인덱스 |
| **Conversation (세션)** | 한 최종사용자와의 대화 단위. 싱글턴 또는 멀티턴 |
| **Turn (턴)** | 세션 내 1개 (사용자 질문 → 콜봇 답변) 쌍. 평가 최소 단위 |
| **QAPair** | 대화에서 추출한 (질문, 봇 답변) + 검색 컨텍스트가 부착된 평가 대상 |
| **Auto Evaluation** | LLM-as-a-Judge가 산출한 턴/세션 자동 평가 결과 |
| **Human Review** | 검수자가 자동 평가를 검토하여 점수를 재평가·확정한 결과 |
| **Final Score** | 휴먼 확정값 우선, 없으면 자동 평가값. `EvaluationRecord.final_scores()` 참조 |
| **Run (배치)** | 파이프라인 1회 실행 단위. `run_id`로 식별·재현 가능 |

---

### 2.2 평가 레벨 구조

```
[Retrieval 레벨]          — RAG가 가져온 컨텍스트 품질 평가
  ├─ context_precision    검색된 청크가 실제로 관련이 있는가 (SLA 0.70)
  └─ context_recall       필요한 정보가 빠진 게 없는가 (SLA 0.70)

[Turn(답변) 레벨]         — 생성된 답변 1건 품질 평가
  ├─ faithfulness         답변이 컨텍스트에 근거하는가 (환각 탐지, SLA 0.80)
  └─ answer_relevance     답변이 질문과 관련이 있는가 (SLA 0.75)

[Session(세션) 레벨]      — 멀티턴 대화 전체 품질 평가 (도메인 옵션)
  ├─ multiturn_consistency  턴 간 답변이 일관적인가
  └─ safety_compliance      PII·컴플라이언스 안전성
```

**진단 (2×2 매트릭스)** — `diagnosis` 옵션 ON 시 자동 분류

```
               Faithfulness ≥ 0.8    Faithfulness < 0.8
Recall ≥ 0.7   ✅ Healthy            🔴 Generation Hallucination
Recall < 0.7   🟡 Retrieval Failure  🔴 Both (복합 문제)
```

## 3. 핵심 기능 요구사항

### 3.1 파이프라인 (백엔드)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-01 | CP1: txt/json/csv 콜 로그를 표준 `CallLog` 스키마로 파싱. `min_turn_length=5` 미만 필터 | P0 |
| F-02 | CP2: Parent(1000 words) - Child(200 words, overlap 50) 청킹 + ChromaDB HNSW 인덱싱 | P0 |
| F-03 | CP3: HyDE + Multi-Query(3개) + BM25/Dense Hybrid RRF(k=60) + Cross-Encoder Rerank | P0 |
| F-04 | CP3.5: 대화 → (User질문, Bot답변) QAPair 추출 (연속 발화 병합, trivial 필터) | P0 |
| F-05 | CP4: faithfulness·answer_relevance·context_precision·context_recall 4개 메트릭 평가 | P0 |
| F-06 | CP4: faithfulness는 RAGAS claim NLI 분해(기본 ON). 다른 메트릭은 N-샘플 중앙값 | P0 |
| F-07 | CP4: N회 샘플링 → 중앙값 + `confidence=max(0,1-std/0.5)` + `is_low_confidence` 플래그 | P1 |
| F-08 | CP5: SLA 임계값 기반 콜 플래그 + mean/median/P10/P90 통계 집계 | P0 |
| F-09 | CP6: HTML/JSON 리포트 + 회귀 감지(고정임계 or 순열검정) + Slack 알림(`urllib.request`) | P1 |
| F-10 | 멱등 재개 (--resume): CP3은 스테이지 단위, CP4는 qa_id 항목 단위 체크포인트 | P1 |
| F-11 | Mock 모드: 결정적 해시 기반 응답·임베딩(64차원)으로 전체 파이프라인 로컬 실행 | P1 |
| F-12 | 비용 가드: 모델별 USD 가격표(`_DEFAULT_PRICING`) 기반 실행당 예산 상한 (circuit breaker) | P1 |
| F-13 | CP4: CoT 강제 평가 — answer_relevance/context_precision/context_recall에 단계별 추론(근거→점수) 적용해 점수 선결정 편향 차단 (`cot_steps` 기록) | P1 |
| F-14 | CP4: 역방향 검증 — faithfulness/answer_relevance를 순방향+역방향으로 평가, `consistency_score`>임계 시 저신뢰 플래그 → 환각 누락 탐지 강화 | P1 |
| F-15 | CP4: 정답성(answer_correctness) — `ground_truth` 대비 claim F1(TP/FP/FN)+의미 유사도. '충실하지만 틀린 답변' 포착. 동시에 answer_relevance에 정답 주입(참조 기반 채점)으로 judge-사람 일치도 향상 | P1 |
| F-16 | CP4: 대화 맥락 주입 — 턴 평가 시 직전 N턴 이력을 프롬프트에 주입해 지시대명사·생략 후속 턴 오채점 제거 (추가 LLM 호출 없음) | P1 |
| F-17 | CP4: 적정 거절 판정 — "정보 없음/안내 불가"가 정당하면(컨텍스트에 근거 부재) faithfulness/answer_relevance 감점 면제(`abstention` 플래그) → 정당한 거절의 거짓 실패 제거 | P1 |
| F-18 | CP4: 결정적 수치 가드 — 답변의 숫자·금액·기간·날짜를 컨텍스트와 정규식 대조해 수치 환각을 faithfulness에서 감점(`numeric_flags`). LLM 호출 0 | P1 |
| F-19 | CP4: 휴먼 정합 자동 보정 — 골든셋(judge→human)으로 isotonic/platt/linear 보정맵 학습 후 점수 교정(`calibrated_from` 보존) + SLA 임계 F1 최대화 자동 튜닝 | P2 |
| F-20 | KB: 고객사 지식 구축 — Knowledge Base 화면에서 문서(제목·유형·내용) 추가 시 CP2 child 청크(200자/overlap 50) 기준으로 청킹·저장(`kb_documents` 테이블), KB 현황(문서·청크 수)에 반영. 테넌트 격리·삭제 지원 | P1 |
| F-21 | KB: 파일 업로드 — 드래그앤드롭/선택으로 다양한 포맷(txt·md·csv·tsv·json·xml·yaml·html·pdf·docx·xlsx) 업로드 시 텍스트 추출 → F-20 구축 흐름으로 저장. 확장자 기반 source_type 자동 감지, 다중 파일·파일당 5MB 상한, 미지원/빈/파싱실패 파일은 개별 안내 | P1 |

### 3.3 고급 평가 기법 (16종 토글)

| 옵션 | 클래스 | 기법 | 기본값 |
|------|--------|------|--------|
| `cot` | `LLMJudge` (CoT 프롬프트) | 근거 먼저→점수 나중 단계 추론으로 점수 선결정 편향 차단 | **on** |
| `reverse` | `LLMJudge._apply_reverse` | 순방향+역방향 양방향 평가 + 불일치 저신뢰 플래그 | off |
| `correctness` | `CorrectnessEvaluator` | 정답 대비 claim F1+의미유사도(정답성) + 참조 기반 채점 | off |
| `context_injection` | `LLMJudge._build_prompt` | 직전 N턴 대화 맥락 주입 → 후속 턴 오채점 제거 | off |
| `abstention` | `AbstentionDetector` | 정당한 거절/모름 감점 면제 (거짓 실패 제거) | off |
| `numeric_guard` | `numeric_guard` | 결정적 수치·날짜 대조로 수치 환각 포착 (비용 0) | off |
| `auto_calibration` | `AutoCalibrator` | 골든셋 보정맵(isotonic/platt/linear) + SLA 자동 튜닝 | off |
| `calibration` | `JudgeCalibrator` | 앵커+길이정규화+G-Eval (logprob or 다중샘플 기댓값) | off |
| `ensemble` | `EnsembleJudge` | 다중 Judge + 불일치 에스컬레이션 (2개 미만 시 단일 폴백) | off |
| `meta_eval` | `MetaEvaluator` | 골든셋 대비 Spearman ρ / Cohen κ / MAE | off |
| `nugget` | `NuggetRecallEvaluator` | 핵심 정보 추출 → 컨텍스트 매칭 (GT-free recall) | off |
| `diagnosis` | `RetrievalGenerationDiagnoser` | faithfulness×recall 2×2 분류 | **on** |
| `statistics` | `statistics_ext` | 부트스트랩 CI + 순열검정 기반 회귀 | **on** |
| `routing` | `EvaluationRouter` | 저신뢰 항목 추가 샘플 + active sampling 검수 큐 | off |
| `ppi` | `HeuristicClassifier` + `ppi_mean()` | 분류기 전체 예측 + 소량 LLM 보정 추정 | off |
| `domain` | `DomainMetricsEvaluator` | 멀티턴 일관성 + PII 안전성 | off |

> **답변 품질 정확도 강화 묶음(F-15~F-19)**: `correctness`·`abstention`·`numeric_guard`는 "충실하지만 틀린 답변", "정당한 거절", "수치 환각"이라는 기존 4메트릭의 사각지대를 메우고, `context_injection`은 멀티턴 후속 턴 오채점을, `auto_calibration`은 judge-사람 척도 격차를 교정한다.

## 4. 비기능 요구사항

| 항목 | 요구사항 |

| **CI/CD** | GitHub Actions: ruff lint + pytest + Docker build |

## 5. SLA 기준값 (기본값, 가입자별 조정 가능)

| 메트릭 | SLA 임계값 | 설명 |
|--------|-----------|------|
| `faithfulness` | 0.80 | 환각 없이 컨텍스트 근거 답변 |
| `answer_relevance` | 0.75 | 질문과 관련된 답변 |
| `context_precision` | 0.70 | 검색 정확도 |
| `context_recall` | 0.70 | 검색 재현율 |
| `answer_correctness` | 0.75 | 정답(ground_truth) 대비 정답성 (correctness 활성 시) |

임계값은 `config/settings.yaml`의 `cp5.sla_thresholds` 또는 Admin Console Settings에서 가입자별로 조정 가능. 1개라도 미달한 콜은 `flagged_call_ids`에 포함(`sorted()` 정렬 반환).
