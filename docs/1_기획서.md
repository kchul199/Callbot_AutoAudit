## 1. 제품 개요

### 1.1 배경 및 목적

SaaS형 생성형 콜봇은 가입자(고객사)가 업로드한 지식 데이터를 RAG(Retrieval-Augmented Generation) 시스템으로 색인하고, 최종 사용자(가입자의 고객)의 문의에 LLM이 답변을 생성한다. 이 과정에서 다음 문제가 발생한다.

| 문제 | 영향 |
|------|------|
| LLM 환각(Hallucination) — 지식 베이스에 없는 내용을 답변 | 고객 신뢰 손상, 민원 |
| 검색 실패 — 관련 문서가 있어도 RAG가 찾지 못함 | 답변 품질 저하 |
| Ground Truth 부재 — 정답 없이 품질을 객관적으로 측정 불가 | 지표 부재, 개선 방향 불명확 |
| 멀티테넌트 운영 — 가입자별 품질 현황을 개별 모니터링 불가 | 운영 효율 저하 |

**CallBot AutoAudit**은 위 문제를 해결하기 위한 **RAG 품질 자동 감사 파이프라인 + 관리 콘솔**이다.

- Ground Truth 없이도 신뢰할 수 있는 품질 지표 산출
- LLM-as-a-Judge로 자동 평가 후 **인간 검수 → 확정** 워크플로우
- 가입자별 완전 격리된 멀티테넌트 구조

---

### 1.2 제품 범위

```
범위 IN:
  - CP1~CP6 평가 파이프라인 (콜 로그 → 품질 리포트)
  - Admin Console (웹 대시보드)
  - REST API (백엔드)
  - 로컬 개발 Mock 모드

범위 OUT:
  - 콜봇 자체(답변 생성) 구현
  - 가입자 온보딩 / 결제 시스템
  - 콜 로그 수집 에이전트
```

## 2. 핵심 도메인 모델

### 2.1 용어 정의

| 용어 | 정의 |
|------|------|
| **Tenant** | 콜봇을 운영하는 가입자(고객사). KB·대화이력·평가가 테넌트 단위로 격리 |
| **Knowledge Base (KB)** | 테넌트가 업로드한 지식 데이터로 만든 RAG 인덱스 |
| **Conversation (세션)** | 한 최종사용자와의 대화 단위. 싱글턴 또는 멀티턴 |
| **Turn (턴)** | 세션 내 1개 (사용자 질문 → 콜봇 답변) 쌍. 평가 최소 단위 |
| **Auto Evaluation** | LLM-as-a-Judge가 산출한 턴/세션 자동 평가 결과 |
| **Human Review** | 검수자가 자동 평가를 검토하여 점수를 재평가·확정한 결과 |
| **Final Score** | 휴먼 확정값 우선, 없으면 자동 평가값 (신뢰 가능한 최종 지표) |
| **Run (배치)** | 파이프라인 1회 실행 단위. `run_id`로 식별·재현 가능 |

---

### 2.2 평가 레벨 구조

```
[Retrieval 레벨]          — RAG가 가져온 컨텍스트 품질 평가
  ├─ context_precision    검색된 청크가 실제로 관련이 있는가
  └─ context_recall       필요한 정보가 빠진 게 없는가

[Turn(답변) 레벨]         — 생성된 답변 1건 품질 평가
  ├─ faithfulness         답변이 컨텍스트에 근거하는가 (환각 탐지)
  └─ answer_relevance     답변이 질문과 관련이 있는가

[Session(세션) 레벨]      — 멀티턴 대화 전체 품질 평가
  ├─ multiturn_consistency  턴 간 답변이 일관적인가
  └─ safety_compliance      PII·컴플라이언스 안전성
```

**진단 (2×2 매트릭스)**

```
               Faithfulness 높음     Faithfulness 낮음
Recall 높음    ✅ Healthy            🔴 Generation Hallucination
Recall 낮음    🟡 Retrieval Failure  🔴 Both (복합 문제)
```

## 3. 핵심 기능 요구사항

### 3.1 파이프라인 (백엔드)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-01 | CP1: txt/json/csv 콜 로그를 표준 `CallLog` 스키마로 파싱 | P0 |
| F-02 | CP2: Parent-Child 청킹 + ChromaDB 벡터 인덱싱 | P0 |
| F-03 | CP3: HyDE + Multi-Query + BM25/Dense Hybrid + Cross-Encoder 검색 | P0 |
| F-04 | CP4: 4개 핵심 메트릭 LLM-as-a-Judge 평가 | P0 |
| F-05 | CP4: N회 샘플링 → 중앙값 + 신뢰도 플래그 | P1 |
| F-06 | CP5: SLA 임계값 기반 콜 플래그 + 통계 집계 | P0 |
| F-07 | CP6: HTML/JSON 리포트 + 회귀 감지 + Slack 알림 | P1 |
| F-08 | 멱등 재개 (--resume): 중단된 평가를 체크포인트에서 재개 | P1 |
| F-09 | Mock 모드: API 키·GPU 없이 전체 파이프라인 로컬 실행 | P1 |
| F-10 | 비용 가드: 실행당 USD 예산 상한 (circuit breaker) | P1 |

### 3.2 고급 평가 기법 (옵션 토글)

| 옵션 | 기법 | 기본값 |
|------|------|--------|
| `calibration` | 편향 보정 + G-Eval logprob | off |
| `ensemble` | 다중 Judge 앙상블 | off |
| `meta_eval` | 골든셋 대비 Judge 메타평가 | off |
| `nugget` | Nugget 기반 GT-free recall | off |
| `diagnosis` | 검색 vs 생성 2×2 진단 | **on** |
| `statistics` | 부트스트랩 CI + 유의성 회귀 | **on** |
| `routing` | 저신뢰 항목 추가 샘플링 | off |
| `ppi` | Prediction-Powered Inference (대량 저비용) | off |
| `domain` | 멀티턴 일관성 + PII 안전성 | off |

### 3.3 Admin Console (프론트엔드)

| ID | 화면 | 핵심 기능 | 우선순위 |
|----|------|-----------|----------|
| U-01 | Overview | KPI 카드 + 메트릭 현황 + 추이 + SLA 미달 목록 + drill-in/out | P0 |
| U-02 | Conversations | 세션 목록 + 대화 타임라인 + 근거 하이라이트 | P0 |

| U-05 | Evaluations | 필터 탐색 + Evidence 드로어 | P1 |
| U-06 | Trends | 배치별 추이 그래프 + 일치도 드릴인 | P1 |

## 5. SLA 기준값

| 메트릭 | SLA 임계값 | 설명 |
|--------|-----------|------|
| `faithfulness` | 0.80 | 환각 없이 컨텍스트 근거 답변 |
| `answer_relevance` | 0.75 | 질문과 관련된 답변 |
| `context_precision` | 0.70 | 검색 정확도 |
| `context_recall` | 0.70 | 검색 재현율 |

임계값은 `config/settings.yaml`의 `cp5.sla_thresholds` 또는 Admin Console Settings에서 가입자별로 조정 가능.
