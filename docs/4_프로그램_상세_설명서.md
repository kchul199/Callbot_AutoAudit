### 2.1 `core/types.py` — 데이터 모델 중앙 정의

파이프라인 전체에서 공유하는 Pydantic 모델의 원천.

**주요 클래스:**

| 클래스 | 용도 |
|--------|------|
| `ConversationTurn` | 단일 대화 턴 (role: user/bot/system, content, timestamp) |
| `CallLog` | 콜 로그 표준 스키마 (call_id, subscriber_id, turns) |
| `Chunk` | Parent-Child 청킹 단위 (chunk_id, level, parent_chunk_id) |
| `RetrievedContext` | 검색 결과 단위 (score, bm25_score, dense_score) |
| `RetrievalResult` | 한 질의의 전체 검색 결과 (hyde_query, sub_queries, contexts) |
| `QAPair` | 대화→(질문, 봇답변) 쌍 + 검색 컨텍스트 |
| `MetricScore` | 단일 메트릭 점수 + 근거 + 신뢰도 |
| `EvaluationRecord` | 턴/세션 평가 전체 결과 (휴먼 재평가 포함) |
| `AuditSummary` | 배치 집계 요약 (SLA 판정, 통계) |

**`EvaluationRecord.final_scores()` 메서드:**
```python
def final_scores(self) -> dict[str, float]:
    """Final = 사람 확정값 우선, 없으면 자동 점수"""
    out = {ms.metric: ms.score for ms in self.scores}
    out.update(self.human_scores)   # 사람이 수정한 메트릭만 덮어씀
    return out
```

### 2.2 `core/llm_client.py` — LLM Provider 추상화

```python
class LLMProvider(ABC):
    @abstractmethod
    async def complete(prompt, temperature, max_tokens) → str
    
    @abstractmethod
    async def embed(text) → list[float]
```

**구현체:**
- `OpenAIProvider`: `openai.AsyncOpenAI` 사용, `text-embedding-3-large` 임베딩
- `AnthropicProvider`: `anthropic.AsyncAnthropic` 사용
- `AzureProvider`: Azure OpenAI 엔드포인트 연동
- `GeminiProvider`: Google Gemini API 연동
- `MockProvider`: 해시 기반 결정적 응답 (API 키 불필요)

```python
class CostTracker:
    # 입출력 토큰 누적 추적
    # budget_usd 초과 시 BudgetExceededError 발생 (circuit breaker)
```

**재시도 전략 (tenacity):**

### 2.5 `cp2_knowledge_base/chunker.py` — Parent-Child 청커

```python
class ParentChildChunker:
    parent_chunk_size: int = 1000   # 단어 수
    child_chunk_size: int = 200
    chunk_overlap: int = 50
    
    def chunk(call_log: CallLog) → list[Chunk]
    def _split_text(text: str, size: int, overlap: int) → list[str]
```

**청킹 알고리즘:**
1. CallLog의 모든 턴을 하나의 텍스트로 연결
2. Parent 크기(1000 words)로 슬라이딩 윈도우 분할
3. 각 Parent를 Child 크기(200 words)로 재분할 (overlap=50)
4. Child는 `parent_chunk_id`로 부모 참조

### 2.7 `cp4_evaluator/judge.py` — LLM Judge 평가 엔진

#### 평가 흐름

```python
class LLMJudge:
    async def evaluate_pair(qa_pair: QAPair) → EvaluationRecord:
        # 4개 메트릭을 gather_with_concurrency로 병렬 실행
        scores = await gather_with_concurrency([
            self._eval_metric("faithfulness", ...),
            self._eval_metric("answer_relevance", ...),
            self._eval_metric("context_precision", ...),
            self._eval_metric("context_recall", ...),
        ], concurrency=4)
    
    async def _eval_metric(metric, ...) → MetricScore:
        # N샘플 병렬 실행
        raw_scores = await gather_with_concurrency(
            [self._single_sample(metric, ...) for _ in range(n_samples)],
            concurrency=n_samples
        )
        # 중앙값 + 표준편차 계산
        score = statistics.median(raw_scores)
        std = statistics.pstdev(raw_scores)
        is_low_confidence = std > low_confidence_std
```

### 2.9 `cp5_aggregator/aggregator.py` — 결과 집계

```python
class ResultAggregator:
    def aggregate(
        records: list[EvaluationRecord],
        run_id: str,
        options: EvaluationOptions | None
    ) → AuditSummary:
        
        # 메트릭별 점수 집계
        for metric in metrics:
            scores = [r.final_scores().get(metric) for r in records]
            mean = statistics.mean(scores)
            median = statistics.median(scores)
            p10 = _percentile(scores, 10)
            p90 = _percentile(scores, 90)
            
            # 부트스트랩 CI (statistics 옵션 ON 시)
            if options.statistics.enabled:
                ci = bootstrap_ci(scores, n=1000, level=0.95)
        
        # SLA 플래그
        flagged = self._flag_calls(records)
    
    def _flag_calls(records) → list[str]:
        """1개라도 SLA 미달 메트릭이 있는 call_id 목록"""
        flagged = set()
        for rec in records:
            for score in rec.scores:
                threshold = SLA_THRESHOLDS.get(score.metric, 0.7)
                if score.score < threshold:
                    flagged.add(rec.call_id)
        return list(flagged)
```

## 3. 주요 설계 패턴

### 3.1 비동기 배치 처리

```python
async def gather_with_concurrency(coros: list, concurrency: int) → list:
    """세마포어로 동시 실행 수를 제한하는 gather"""
    semaphore = asyncio.Semaphore(concurrency)
    
    async def _limited(coro):
        async with semaphore:
            return await coro
    
    return await asyncio.gather(*[_limited(c) for c in coros])
```

- CP2 임베딩: concurrency=10
- CP3 QA 검색: concurrency=5  
- CP4 평가: concurrency=5

### 3.4 결정적 Mock 응답

```python
class MockProvider(LLMProvider):
    async def complete(prompt, temperature, max_tokens) → str:
        # 프롬프트 해시 → 미리 정의된 응답 템플릿 선택
        # temperature 무시 → 완전 결정적
        idx = hash(prompt) % len(MOCK_RESPONSES)
        return MOCK_RESPONSES[idx]
    
    async def embed(text) → list[float]:
        # 텍스트 해시 → 384차원 결정적 벡터
        seed = int(hashlib.md5(text.encode()).hexdigest(), 16)
        rng = random.Random(seed)
        return [rng.uniform(-1, 1) for _ in range(384)]
```

## 6. 파이프라인 CLI 옵션 (`run_pipeline.py`)

| 옵션 | 설명 | 예시 |
|------|------|------|
| `--data` | 입력 경로 (파일 또는 디렉토리) | `--data data/raw/` |
| `--until` | 중간 종료 CP | `--until cp3` |
| `--reindex` | ChromaDB 재인덱싱 | `--reindex` |
| `--resume` | 기존 run 재개 | `--resume run_abc123` |
| `--enable` | 기법 활성화 (쉼표 구분) | `--enable calibration,ensemble` |
| `--disable` | 기법 비활성화 | `--disable diagnosis` |

**사용 예:**
```bash
# 기본 실행
python run_pipeline.py --data data/raw/

# CP3까지만 실행 후 중단
python run_pipeline.py --until cp3

# 중단된 run 재개 (체크포인트 기반)
python run_pipeline.py --resume run_abc123

# 고급 기법 활성화
python run_pipeline.py --enable calibration,ensemble,nugget

# 대량 저비용 모드
python run_pipeline.py --enable ppi,routing

# Mock 모드 실행
AUTOAUDIT_MOCK=1 python run_pipeline.py
```
