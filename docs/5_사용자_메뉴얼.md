## 2-1. Conversation Detail (대화 상세)

### 화면

![Conversation Detail](./screenshots/09_conversation_detail.png)

### 세션 평가 (상단)

세션 전체를 평가한 4가지 지표:

| 지표 | 설명 |
|------|------|
| **해결** (resolution) | 고객 문제 해결 여부 (0.0~1.0) |
| **효율** (efficiency) | 불필요한 턴 반복 없이 간결히 해결 (0.0~1.0) |
| **에스컬레이션** (escalation_handling) | 상담원 연결 필요 → 0.0 / 불필요 → 1.0 |
| **일관성** (multiturn_consistency) | 봇 답변 간 모순 없음 (DomainMetrics 재사용) |

> `gt_similarity`: Ground Truth가 있는 경우 마지막 봇 답변 vs GT 임베딩 cosine 유사도 추가 표시.

### 대화 타임라인

- **고객** 발화: 왼쪽 회색 박스 (턴 0, 2, 4...)
- **콜봇** 답변: 오른쪽 하늘색 박스 (턴 1, 3, 5...)
- **평가 대상 턴**: "멀티턴 · 턴 N" 배지 + 4개 메트릭 점수 배지

**점수 배지 색상:**
- 🟢 초록 (≥ 0.9): 우수
- 🟡 노란 (≥ 0.7): 보통
- 🔴 빨간 (< 0.7): 미달

### 평가 근거 (하단)

"🔍 평가 근거 (턴 N)" 섹션에 검색된 컨텍스트 청크 목록:
- **chunk ID**: 벡터 DB 청크 식별자
- **rerank 점수**: Cross-Encoder 재정렬 점수 (높을수록 관련성 높음)
- **컨텍스트 내용**: 실제 지식 베이스에서 검색된 내용

> **환각 감지**: 답변 텍스트에서 컨텍스트에 없는 내용이 특정 색상(빨간/녹색 밑줄)으로 하이라이트됩니다.

## 3. Run Evaluation (평가 실행)

### 화면

![Run Evaluation](./screenshots/03_run_evaluation.png)

6스텝 마법사 형식으로 평가 배치를 구성합니다.

### Step 1: Judge 모델 선택

| 옵션 | 모델 | 비용 | API 키 |
|------|------|------|--------|
| Anthropic Claude | claude-sonnet-4-5 | $3/1M input | ANTHROPIC_API_KEY |
| OpenAI GPT-4o | gpt-4o | $2.50/1M input | OPENAI_API_KEY |
| Google Gemini | gemini-2.5-pro | $1.25/1M input | GEMINI_API_KEY |
| Azure OpenAI | gpt-4o | $2.50/1M input | AZURE_OPENAI_API_KEY |
| Mock (개발용) | mock | 비용 $0 | 불필요 |

> **임베딩 주의**: Anthropic/Gemini Provider를 선택해도 임베딩은 내부적으로 OpenAI API를 사용합니다. `OPENAI_API_KEY`가 추가로 필요합니다.

**앙상블 Judge**: 2개 이상 선택 시 `ensemble` 옵션이 자동 활성화됩니다.  
불일치 항목(표준편차 > 0.25)은 메타 Judge로 에스컬레이션됩니다.

### Step 2: 평가 레벨 선택

| 레벨 | 설명 | 측정 메트릭 |
|------|------|------------|
| **Retrieval** | RAG 검색 컨텍스트 품질 평가 | context_precision, context_recall |
| **Turn (답변)** | 각 봇 답변의 품질 평가 | faithfulness, answer_relevance |
| **Session (세션)** | 멀티턴 대화 전체 품질 | resolution, efficiency, escalation_handling, multiturn_consistency |

### Step 3: 메트릭 선택

레벨에 따라 선택 가능한 메트릭이 표시됩니다. 기본적으로 전체 선택.

### Step 4: 정확도 방법론 (16종 토글)

| 옵션 | 효과 | 추가 비용 |
|------|------|-----------|
| **cot** | 근거→점수 단계 추론으로 점수 선결정 편향 차단 | 기본 ON (추가 없음) |
| **reverse** | 순방향+역방향 양방향 평가 → 환각 누락 탐지↑ | ~2× (역방향 1회 추가) |
| **correctness** ① | 정답(ground_truth) 대비 정답성 + 정답 주입 채점(②) → "충실하지만 틀린 답변" 포착 | 정답당 +1회 |
| **context_injection** ③ | 직전 N턴 맥락 주입 → "그건 얼마?" 후속 턴 오채점 제거 | 없음 (프롬프트만) |
| **abstention** ④ | 정당한 "정보 없음/거절" 감점 면제 → 거짓 실패 제거 | 거절 답변에만 +1회 |
| **numeric_guard** ⑤ | 숫자·금액·날짜 결정적 대조로 수치 환각 포착 | 없음 (LLM 0) |
| **auto_calibration** ⑦ | 골든셋으로 점수를 사람 척도로 보정 + SLA 자동 튜닝 | 없음 (사후 처리) |
| **calibration** | 앵커/길이 편향 보정 + G-Eval | ~3× (다중샘플) |
| **ensemble** | 다중 LLM 교차검증 → 신뢰성 ↑ | ~2× (2개 Provider) |
| **claim 분해** | faithfulness를 claim NLI로 정밀 측정 | 기본 ON (추가 없음) |
| **nugget recall** | 핵심 정보 추출 매칭 (GT-free recall) | 약간 |
| **multi-sample** | N회 반복 → 분산 기반 신뢰도 | ~3× |
| **diagnosis** | 검색/생성 원인 자동 2×2 분류 | 기본 ON (추가 없음) |
| **statistics** | 부트스트랩 신뢰구간 + 순열검정 회귀 | 기본 ON (추가 없음) |
| **routing** | 저신뢰 항목 추가 샘플링 | 저신뢰 항목에만 |
| **ppi** | 분류기 예측 + 소량 LLM 보정 (대량 저비용) | 크게 절감 |
| **domain** | PII 안전성 + 멀티턴 일관성 | 약간 |

> **cot + reverse 조합 (권장)**: `cot`는 기본 켜져 있어 추가 비용 없이 정확도를 높입니다.
> 중요한 감사에는 `reverse`를 함께 켜면 순방향에서 놓친 환각을 역방향이 잡아내고,
> 두 방향 점수가 0.25 이상 차이나는 항목은 자동으로 "검수 대기"로 분류됩니다.

> **답변 품질 정확도 강화 묶음 (①~⑤,⑦)**: 정답 데이터가 있으면 `correctness`로
> "충실하지만 틀린 답변"을 직접 검증하고(`answer_relevance`엔 정답을 주입해 채점),
> 멀티턴 콜봇이면 `context_injection`(비용 0)으로 후속 턴 오채점을 없앱니다.
> 콜봇 특화로 `abstention`은 정당한 거절을 감점에서 면제하고, `numeric_guard`(비용 0)는
> 요금·기간 같은 수치 환각을 결정적으로 잡습니다. 사람 검수 라벨이 쌓이면
> `auto_calibration`이 자동 점수를 사람 척도로 보정하고 SLA 임계를 자동 튜닝합니다.

**CLI 예시:**
```bash
# 정답 데이터가 있는 정밀 감사 (정답성 + 참조 채점 + 수치 가드)
python run_pipeline.py --enable correctness,numeric_guard

# 멀티턴 콜봇 + 거절 면제 (비용 증가 거의 없음)
python run_pipeline.py --enable context_injection,abstention,numeric_guard

# 검수 라벨(data/golden_set.jsonl) 축적 후 사람 척도 보정
python run_pipeline.py --enable auto_calibration
```

### Step 5: 평가 대상 범위

- **전체**: 모든 미평가 세션
- **미검수만**: 검수 대기 중인 항목
- **기간 지정**: 특정 날짜 범위

### Step 6: 확인 및 실행

구성 요약 확인 후 **실행** 버튼 클릭. Mock 모드에서 즉시 완료, 실 LLM은 배경 처리.

## 4. Review (휴먼 검수 워크스페이스)

### 화면

![Review](./screenshots/04_review.png)

3-pane 레이아웃: 검수 큐 (좌) · 평가 상세 (중) · 재평가 패널 (우)

### 좌측: 검수 큐

우선순위 정렬 (저신뢰 → SLA미달 → 일반 순):
- **턴** 배지(빨간): is_low_confidence=True 항목
- **세션** 배지(주황): 세션 전체 평가
- 진행 현황: `완료 N / 잔여 M`

### 중앙: 평가 상세

**상단 메타정보**: 세션 ID · 가입자 ID · Judge 모델 (예: anthropic/claude-sonnet-4-5)

**탭 전환**:

| 탭 | 내용 |
|----|------|
| **평가 근거** | 검색 컨텍스트 청크 + rerank 점수 |
| **전체 대화** | 세션 타임라인 (맥락 확인용) |

**평가 대상 턴**: 파란색 강조로 표시. 봇 답변 문장 단위로 환각/근거 하이라이트.

**검색된 컨텍스트** 목록:
- `chunk_id` + rerank 점수 (높을수록 관련성 ↑)
- 실제 지식 베이스 내용

**멀티턴 컨텍스트**: "직전 대화 맥락 (N턴)" 토글로 이전 대화 확인 가능.

### 우측: 재평가 패널

각 메트릭별:
1. **자동 점수** 확인 (예: "자동 1.00")
2. **5단계 버튼** (0 / 0.25 / 0.5 / 0.75 / 1) 으로 점수 수정
3. **"자동과 동의"** 선택으로 자동 점수 승인

**보류 레이블** (다중 선택):
- `hallucination` — 환각 (컨텍스트에 없는 정보)
- `missing_context` — 검색 실패 (관련 문서 없음)
- `off_topic` — 질문과 무관한 답변
- `unsupported_claim` — 근거 없는 주장

**하단 버튼**:

| 버튼 | 동작 | `review_status` |
|------|------|-----------------|
| **승인 & 다음** | 현재 점수로 확정 후 다음 항목 | `approved` (변경 없음) / `overridden` (수정됨) |
| **보류** | 나중에 다시 검수 | `skipped` |

> **Final Score 원칙**: `human_scores`에 있는 메트릭만 자동 점수를 덮어씁니다. 나머지 메트릭은 자동 점수가 그대로 Final Score입니다.

### 🆕 고객사 지식 구축

화면 상단의 **"📥 고객사 지식 구축"** 카드에서 **① 파일 업로드** 또는 **② 직접 입력**으로 지식을 추가합니다.

**① 파일 업로드 (다양한 포맷)**

드롭존에 파일을 **끌어다 놓거나 클릭해 선택**하면 텍스트가 추출되어 KB에 추가됩니다.

| 분류 | 지원 포맷 |
|------|-----------|
| 텍스트 | `.txt` `.md` `.markdown` `.rst` `.log` `.text` `.xml` `.yaml` `.yml` |
| 표/구조화 | `.csv` `.tsv` `.json` |
| 웹 | `.html` `.htm` (태그 자동 제거) |
| 문서 | `.pdf` `.docx`(Word) `.xlsx`(Excel) |

- **다중 파일** 동시 업로드 가능, 파일당 **최대 5MB**.
- 문서 유형은 확장자로 **자동 감지**(PDF/Word/Excel/CSV…)됩니다.
- 미지원/빈/파싱 실패 파일은 파일별로 사유가 표시되고, 나머지는 정상 처리됩니다.
- 스캔 이미지 PDF처럼 텍스트가 없으면 추출 실패로 안내됩니다.

**② 직접 입력**

| 입력 | 설명 |
|------|------|
| **문서 제목** | 예: "5G 요금제 안내" (필수) |
| **유형** | 정책 / FAQ / 약관 / 매뉴얼 / 상품정보 / 기타 |
| **문서 내용** | 정책·약관·FAQ 본문 붙여넣기 (필수). 입력 중 글자수·예상 청크 수 실시간 표시 |

- 추가 시 내용이 CP2 child 청크(200자, overlap 50) 기준으로 청킹되어 저장되고, 상단 통계(문서·청크 수)와 아래 **"📚 구축된 지식 문서"** 목록에 즉시 반영됩니다.
- 각 문서는 제목·유형·글자수·청크 수·등록일과 함께 표시되며 **삭제** 가능합니다.
- 문서는 테넌트(고객사)별로 격리됩니다.

> 데모 단계에서는 구축 문서가 서버 인메모리(SQLite `kb_documents`)에 저장됩니다.
> 운영 전환 시 이 문서들이 CP2 인덱싱 파이프라인 입력이 되어 실제 검색 대상 벡터로 색인됩니다.

### 커버리지 갭

Context Recall이 낮았던 질의 목록. KB에 해당 주제 문서가 부족함을 나타냄.

**활용법**: 갭 목록의 질의를 분석해 부족한 주제를 파악하고, **"고객사 지식 구축"에서 해당 문서를 추가**해 KB를 보강합니다.

### SLA 임계값

각 메트릭별 임계값 조정. 이 값보다 낮은 점수는 SLA 미달로 플래그.

### 평가 프로필

| 프로필 | 활성 기법 | 적합한 상황 |
|--------|----------|------------|
| **기본** | cot + diagnosis + statistics | 일반 모니터링 (CoT 기본 ON) |
| **빠른 점검** | diagnosis + statistics (cot 끔) | 대량 처리, 비용 절감 |
| **고신뢰** | cot + reverse + calibration + ensemble | 정확도 최우선, 환각 누락 최소화 |
| **검색 진단** | cot + nugget + diagnosis | 검색 품질 집중 분석 |
| **안전성 감사** | reverse + domain + nugget | PII·컴플라이언스 + 환각 양방향 검증 |

### Judge 자격증명

provider별 API 키 등록 상태를 `등록됨`(초록)/`키 미등록`(주황) 배지로 표시합니다.
**provider 칩을 클릭하면 등록 모달**이 열려 화면에서 직접 키를 관리할 수 있습니다.

**모달에서 할 수 있는 것:**
- **API Key 입력** — 표시/숨김 토글 지원. 저장 시 마스킹(`••••••••1234`)되어 보관되며 평문은 다시 표시되지 않습니다.
- **Azure 전용 필드** — Endpoint · API Version · Deployment 입력
- **openai/anthropic** — 선택적 Base URL(호환 게이트웨이)
- **저장/삭제/취소** — 수동 등록 키는 삭제 가능(환경변수 등록은 영향 없음)

> 등록 출처가 함께 표시됩니다: `등록됨(수동)`은 모달로 등록한 키(마스킹 노출),
> `등록됨(환경변수)`은 서버 `.env`로 등록된 키입니다.

키는 모달 외에 서버 환경변수로도 관리할 수 있습니다:

```bash
# .env 파일 (git 제외됨)
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
GEMINI_API_KEY=...
AZURE_OPENAI_API_KEY=...
```

> **보안**: 수동 등록 키는 데모 단계라 서버 인메모리에 마스킹 형태로만 보관되어
> 재시작 시 초기화됩니다(운영 전환 시 암호화 영속 저장소로 교체 — `DataAccess._credentials`).

## 9. 파이프라인 CLI 사용법

Admin Console 없이 직접 파이프라인을 실행하는 경우.

### 기본 실행

```bash
# 전체 파이프라인 (CP1~CP6)
python run_pipeline.py --data data/raw/

# Mock 모드 (API 키, GPU 불필요)
AUTOAUDIT_MOCK=1 python run_pipeline.py --data data/raw/
```

### 단계별 실행

```bash
# CP3(검색)까지만 실행하고 중단
python run_pipeline.py --until cp3

# KB 재인덱싱 후 실행
python run_pipeline.py --reindex --data data/raw/
```

### 재개 (Resume)

이전 실행이 중단된 경우 체크포인트에서 재개합니다.  
CP3 체크포인트 존재 시 CP1/CP2(로그 파싱+인덱싱)를 건너뛰고, CP4는 이미 완료된 qa_id를 skip합니다.

```bash
# 실행 중인(또는 중단된) run_id 확인
ls data/results/

# 재개
python run_pipeline.py --resume run_abc12345
```

### 고급 기법 활성화/비활성화

```bash
# 정확도 향상 (역방향 검증, CoT는 기본 ON)
python run_pipeline.py --enable reverse

# 신뢰성 극대화 (역방향 + 앙상블 + 보정)
python run_pipeline.py --enable reverse,calibration,ensemble

# 콜봇 안전성 감사
python run_pipeline.py --enable domain,nugget

# 대량 저비용 처리 (CoT 끄고 분류기 기반)
python run_pipeline.py --enable ppi,routing --disable cot

# 기법 비활성화
python run_pipeline.py --disable diagnosis

# 하위 필드 토글 (점 표기)
python run_pipeline.py --enable calibration.g_eval_logprobs
```

## 12. 자주 묻는 질문

**Q. API 키 없이 테스트할 수 있나요?**  
A. `AUTOAUDIT_MOCK=1` 환경변수로 Mock 모드를 활성화하면 openai·anthropic 키 없이 전체 기능을 테스트할 수 있습니다. Mock 임베딩(64차원)과 결정적 평가 점수를 사용합니다.

**Q. Anthropic Claude를 Judge로 선택했는데 임베딩 에러가 납니다.**  
A. Anthropic Provider는 임베딩을 지원하지 않아 내부적으로 OpenAI API를 사용합니다. `OPENAI_API_KEY`를 추가로 등록해야 합니다.

**Q. 평가가 중간에 실패하면 처음부터 다시 해야 하나요?**  
A. `--resume run_abc123` 옵션으로 체크포인트에서 재개합니다. CP4 평가는 `qa_id` 항목 단위로 저장되어 완료된 항목은 재평가하지 않습니다.

**Q. faithfulness 점수가 낮게 나왔을 때 원인은?**  
A. Conversation Detail에서 해당 턴을 클릭하여 claim 단위 NLI 판정 결과를 확인하세요. "unsupported" 또는 "contradicted" claim이 환각 원인입니다. `--enable diagnosis` 옵션으로 검색 실패인지 생성 문제인지 자동 진단도 가능합니다.

**Q. SLA 임계값을 조정하려면?**  
A. Settings 화면에서 가입자별로 조정하거나, `config/settings.yaml`의 `cp5.sla_thresholds`를 수정합니다.

**Q. Settings에서 저장한 설정이 서버 재시작 후 초기화됩니다.**  
A. 현재 설정은 `DataAccess._settings` 인메모리 저장이라 서버 재시작 시 기본값으로 돌아갑니다. 영구 저장이 필요하면 `config/settings.yaml`의 `cp5.sla_thresholds`를 직접 수정하세요. (운영 시 SQLite/Redis 영속화 예정)

**Q. Knowledge Base의 source_types가 문서 유형이 아니라 ID처럼 보입니다.**  
A. `source_types` 필드는 현재 `source_call_id` 값들의 목록입니다. 향후 실제 문서 유형(json/txt/csv) 분류로 개선될 예정입니다.

**Q. PII(개인정보)가 포함된 답변은 어떻게 처리되나요?**  
A. `domain` 옵션 활성화 시 `DomainMetricsEvaluator.detect_pii()`가 정규식으로 즉시 탐지합니다 (LLM 불필요). 주민번호·카드번호·전화번호·계좌번호 패턴이 감지되면 `safety_compliance` 점수가 즉시 0.0이 됩니다.

**Q. 새 콜 로그를 추가하려면?**  
A. `data/raw/` 디렉토리에 파일을 추가한 후 `python run_pipeline.py --reindex --data data/raw/`를 실행합니다. `--reindex`로 기존 KB를 삭제 후 재생성합니다.

**Q. Slack 알림이 오지 않습니다.**  
A. Settings에서 Slack Webhook URL을 등록하고, `config/settings.yaml`의 `cp6.notify_slack: true`를 확인하세요. Slack 알림은 `stdlib urllib.request`를 사용하므로 추가 설치 불필요.

**Q. Mock 모드의 점수가 실제 품질을 반영하나요?**  
A. 반영하지 않습니다. Mock 점수는 토큰 중첩 기반 휴리스틱으로 0.5~1.0 범위에서 생성됩니다. 파이프라인 동작 검증용이며, 실제 품질 측정은 실제 LLM API 키로 실행해야 합니다.

**Q. G-Eval logprob 옵션이 동작하지 않습니다.**  
A. `g_eval_logprobs=True`는 `provider.complete_with_logprobs()` API를 지원하는 Provider에서만 동작합니다. 미지원 시 자동으로 다중 샘플 기댓값(3회 샘플링 평균)으로 graceful degrade됩니다.
